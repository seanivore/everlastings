## WS2 — Products surface + sold-policy/state reconciliation + scheduled publish

> **🎯 Headline — full lifecycle on a seeded piece: create-draft → fill → preview → publish.** New product → the editor opens blank → fill the authoritative set (title, slug, headline, description, price, quantity, product_type, story_card, features, materials, care, shipping, dimensions W·D·H, weight, hero + ≥5 gallery, alt on every media). A partial New that's closed **persists as a draft** only once `title` + `price` are present (a truly-blank close writes no row) — proving the create-minimum validator (Phase 2.7) lets a partial draft save. Publish is **disabled until previewed**: click Preview → the `/product/<slug>?preview=<token>` page opens carrying the real Publish → publish there → the piece goes Live on `/shop` and a real test checkout completes on it. The `product_type` picker offers **`miniature` only** (never printable/storybook).

4. **Available-OFF on a LIVE piece → Draft, NOT Sold.** On a published, in-stock piece toggle Available off → the server sets `is_published=false` (response carries `unpublished:true`), `computeState` resolves to **draft** (yellow LED), the piece leaves `/shop`, and the row moves to the Draft tab — it does **not** land in Sold. Toggle Available back on from the row → it prompts to add stock if quantity is 0, then re-runs the publish flow (`?_action=publish`) → back Live with **no duplicate Stripe product** (`stripe_product_id` already set → Stripe create is a no-op the second time).
5. **qty0 from a real sale → Sold tab; Sold persists until Archive.** Buy the last unit of a qty-1 piece → the webhook `record_sale` drives `quantity`→0 + `available`→false → the piece shows **"Sold"** (the word "Sold," never "Sold out"), lands in the **Sold** tab, and **stays there** (a browsable record) until the maker Archives it. Precedence holds: `archived > draft > staged-edits > sold(qty0) > live` — a sold-then-archived piece reads Archived, not Sold. The row LED colors **all five** states (green live, orange edits, yellow draft, blue sold, purple-gray archived — `products-app.js:91`); sold + archived **ALSO** appear as tabs (both the LED color AND a tab, not either/or); live/draft/edits blink, sold/archived are steady.
6. **Two-tier validation (lenient create / full publish gate).** Create accepts a DB-satisfiable minimum (a partial draft persists — item 4's blank-close is the boundary). **Publish** enforces the full authoritative set + `alt` on every image/media entry; the six auto-generated fields (`seo_title, seo_description, checkout_name, checkout_description, checkout_image, seo_thumbnail`) are **never** blocking — leave them blank and publish still succeeds, generating them server-side. A publish missing a required field (e.g. only 4 gallery images, or a blank `dimensions`) is **rejected** with a plain-words reason and red field-rings; the same product created as a draft was NOT rejected.
7. **Scheduled publish flips via the daily cron (cron-gated).** Set `scheduled_publish_at` on a ready draft via the schedule popover → a "Scheduled · <when>" chip shows; the control is a real write, never a dead button. Hit `/api/product-feed` **with `Authorization: Bearer <CRON_SECRET>`** (the flip now runs ONLY inside the shared `isCronRequest` gate — a bare/unauthenticated feed GET publishes **nothing**; confirm that first). On the preview the scan is `is_test`-scoped, so it flips **`is_test=true` (TEST) rows** only (Live rows flip solely from the prod cron) → a past-due scheduled draft **flips Live** (via the reused `?_action=publish` handler, so it gets Stripe-create + shape re-validation + `scheduled_publish_at` cleared for free — it fires **once**). An archived-then-scheduled row does NOT go live (the partial index excludes `archived_at IS NOT NULL`). `scheduled_publish_at` is **stripped from the public product projection** (Phase 2.8 — grep a public GET response, the column is absent).
8. **Inline row edits are live-apply.** From a row: edit price → `PUT ?id= {price}` rotates the Stripe price (a new Price, old deactivated — never an in-place edit); edit quantity → live-apply; toggle featured → staged on a published piece, live on a draft (server routes it). A live price/qty/available change **leaves earlier staged copy edits alone** (a lingering `draft` still needs preview+publish or discard).

## Cross-cutting invariants (hold across every workstream)

- **`is_test` isolation.** A test-preview action never touches a live row: a live order id 404s on the test refund/mark-ship path; `GET /api/orders?payment_intent=<a live PI>` returns `{orders:[]}`; the `active_sale` read returns TEST codes (the Stripe key is env-scoped); `activity_log` + orders + products reads are all `isTest`-scoped; seen/unseen uses the `_test` key. CDN keys stay under `test/…` (files `test_…`).
- **Sold-policy consistency across the three enforcers.** The state model is honored identically in the portal's `computeState()` (WS2 — sold = qty0 from a sale, never the toggle), the storefront buy-gate (WS6/WS9 — `published && quantity > 0`), and the webhook decrement (`record_sale` — `available = quantity>0`, `greatest(…,0)` never negative, decrements by multiplicity). Cross-check: available-off→draft (not sold), qty0→sold, sold persists until archive, and a Sold item is never purchasable.
- **Brand separation.** The portal is cool indigo-slate (the reusable template); the storefront's warm-plum brand is untouched except the WS6 fixes + the WS4 struck-price/top-bar/popup additions (which use storefront tokens). No portal token leaks into the shopper pages and vice-versa; no bare hex where a `var(--token)` should be.
- **Reduced-motion preserved.** Portal motion honors `prefers-reduced-motion`; the storefront hero's reduced-motion fallback stays; the WS4 sale popup animation is gated behind `no-preference`.
- **No hard delete anywhere.** "Delete" = archive; everything is revivable (archive↔resurface, sold↔relist, draft↔publish). A price change creates a new Stripe Price and deactivates the old — never an in-place edit.
- **Money in integer cents.** Every price/amount is stored + compared as integer cents; rendered via `formatPrice()` / `PORTAL_DATA.money()`; the struck-price helper computes `Math.round(cents * (1 - value/100))` — never dollars.
- **CommonJS / tsc-clean + function/cron count unchanged** (re-assert the static gate after the final fold): `npx tsc --noEmit` clean, 11/12 functions, 1 cron, GPT `.txt` under 8000, CORS unaffected (`*.vercel.app` allowlist), `main` untouched throughout.
